# KOICA 업무 중심 규정 지도

직제규정 시행세칙 별표 4의 부서·업무와 별표 5의 해외사무소 업무를 시작점으로 규정 간 참조 관계를 탐색하는 로컬 프로토타입입니다. Python 표준 라이브러리와 브라우저만 사용하며 서버 API, 스크립트 CDN, LLM 호출, OpenCrab 계정이 필요하지 않습니다. 글꼴(Noto Sans KR)만 Google Fonts에서 받으며, 받지 못하면 Apple SD Gothic Neo·맑은 고딕으로 표시합니다.

화면은 KOICA AI 디자인 킷(`koica design.md`)의 색(KOICA Blue + 포인트색 Sky Blue, 주의는 Orange)·서체·웹 UI 규칙(버튼·포커스·모서리 8px 이하·최소 글자 크기)을 따릅니다. 비공식 개인 제작물이므로 KOICA 로고(Communication·Authority Mark), VI 기와 모티프, 핵심가치 조합 등 공식 브랜드 자산은 쓰지 않습니다.

## 실행

저장소 루트에서:

```bash
python3 regulation_map/build.py
python3 -m http.server 8873 --bind 127.0.0.1 --directory regulation_map
```

브라우저에서 <http://127.0.0.1:8873>를 엽니다. 빌드 후에는 `index.html`을 파일로 직접 열어도 됩니다. 서버를 시작한 터미널에서 Ctrl+C로 종료합니다.

## 단일 HTML과 GitHub Pages 배포

```bash
python3 regulation_map/build.py
python3 regulation_map/bundle.py   # regulation_map/dist/index.html
```

`bundle.py`는 CSS·데이터·스크립트를 원래 순서대로 한 HTML에 넣습니다(약 13MB, 압축 전송 약 2.6MB). 서버·CDN·API 없이 정적 호스팅이나 파일로 열어도 동작합니다. `dist/`는 빌드 산출물이라 커밋하지 않습니다.

`.github/workflows/regulation-map-pages.yml`이 지도 테스트 → 빌드 → 단일 HTML 생성 → GitHub Pages 배포를 수행합니다. 사람이 `main`에 push한 규정 지도·추출본·`sources.json` 변경은 경로 조건으로 배포되고, ALIO 주간 동기화의 자동 병합은 `GITHUB_TOKEN` push라 다른 워크플로를 깨우지 않으므로 `alio-sync.yml`이 Fly 배포와 함께 이 워크플로를 직접 호출합니다. 규정 원문이 바뀌면 해당 업무 연결은 재검토 전까지 숨겨지고 새 규정·개정 본문은 바로 반영됩니다.

배포된 페이지 상단의 **HTML 내려받기**는 지금 보고 있는 단일 HTML을 `koica-regulation-map-<최근 규정 반영일>.html`로 저장합니다. 인터넷 없이 열리며, 받은 시점의 스냅샷입니다. 여러 파일로 된 개발용 화면과 이미 내려받은 파일에서는 버튼을 표시하지 않습니다. 저장소 설정의 Pages 소스는 **GitHub Actions**여야 합니다. 화면과 데이터 안내에 KOICA 공식 서비스가 아닌 비공식 개인 제작물임을 표시합니다.

## 탐색

1. 왼쪽 부서 검색창에 입력하면 후보가 바로 나타납니다. Enter로 강조된 후보를 선택하거나 ↑↓로 이동한 뒤 Enter, 또는 후보 클릭으로 선택합니다. 별도 드롭다운을 열 필요가 없습니다. 정확한 부서명을 우선 표시하며 띄어쓰기·영문 대소문자 차이를 무시합니다. Escape는 검색을 취소하고, 결과가 없으면 현재 부서를 유지합니다. **실·팀 모두 선택 즉시 부서 전체 규정 지도**가 열립니다. 병합된 지역부서 공통업무도 포함합니다.
   직제 업무분장의 경로에 있는 상위 처·실도 선택할 수 있습니다. 예를 들어 **인공지능전환실**을 선택하면 인공지능전환·정보화팀, 데이터팀, 정보보안팀의 28개 업무를 팀별로 모아 봅니다. 이는 탐색용 묶음으로, 근거 조문·검토 결과·업무분장 번호는 원래 담당부서에 귀속되며 업무 검토 집계에 중복 산입하지 않습니다. 해외사무소도 같은 방식으로 9개 구분의 68개 업무를 모아 봅니다.
   전체 지도는 업무별 연결을 규정명으로 합쳐 중복 없이 표시합니다. 인공지능전환실은 28개 업무의 7종 규정, 데이터팀은 7개 업무의 2종 규정입니다. 노드의 확인 순서는 연결된 업무 중 가장 높은 기존 단계를 따르며, 연결 횟수로 우선순위를 새로 만들지 않습니다. 규정을 누르면 연결된 팀·업무별 판단과 적용 조건·근거를 펼쳐 볼 수 있습니다. **업무로 좁혀보기** 또는 상세의 **이 업무의 규정 지도로 이동**으로 개별 업무를 선택하고, 왼쪽 **전체 규정 지도** 버튼으로 돌아옵니다. 기존 개별 업무 URL은 그대로 해당 업무를 엽니다.
2. 처음에는 **조문 내용을 읽고 연결한 업무→규정 연결**과 매핑표에 있는 내규→상위법령 연결을 표시합니다. 규정 간 참조선은 규정을 선택할 때 해당 규정과 연결된 것만 나타납니다. 업무 지도에는 현재 업무 범위 안의 참조선만 그릴 수 있으므로, `현재 업무 범위 N개`와 **전체 참조 M종 보기**를 함께 표시하고 범위 안에 참조선이 없으면 그렇다고 안내합니다. 아직 검토하지 않은 업무는 미검토로 표시합니다.
3. 규정 노드를 선택하면 업무에서의 역할, 연결 이유, 적용하는 상황, 실제 근거 문구와 조문 전문이 열립니다. 규정 간 참조도 내용검토 설명이 있는 관계와 자동 추출만 된 관계를 구분합니다.
4. **연결된 다른 규정 보기**로 현재 지도 밖의 규정도 탐색합니다. 현재 업무의 우선순위순으로 12종씩 표시하고, 그 업무에서 판단하지 않은 규정은 이름순으로 뒤에 배치합니다. 이전·다음 페이지로 전체 직접 참조를 확인할 수 있습니다.
5. 연결선을 선택하면 참조 원문, 출발 조문, 대상 규정/조문, 양쪽 개정 정보를 확인합니다.
6. **전체 내규·법령으로 이동** 검색은 선택한 내규의 참조 지도나 법령 상세를 엽니다. 업무 연결 표시 전환, 목록 보기, 확대·축소, 배경 드래그를 지원합니다. URL 해시에 부서·업무·중심 규정 상태를 저장하며, 같은 탭에서 주소의 해시를 바꾸거나 다른 링크로 이동해도 해시를 다시 읽어 화면을 맞춥니다(새로고침 불필요).
   지도는 실제 크기로 그립니다. **100% = 지도 1단위가 화면 1px**이며, 기본 배율은 규정명이 약 13px 이상 보이도록 폭 맞춤과 92% 중 큰 값입니다. 화면보다 크면 지도 안에서 스크롤·마우스 드래그로 이동하고 −/＋, 트랙패드 핀치(Ctrl/⌘+휠)로 확대합니다. **전체 맞춤**은 지도 전체를 한 화면에 보여주며, 글자가 읽기 크기보다 작아지면 안내를 표시합니다. 배율 버튼을 누르면 읽기 크기로 돌아갑니다. 모바일에서도 상위법령이 연결된 범위는 지도로 시작합니다.
   **지도가 기본 보기**이며, 모바일에서 매핑된 상위법령이 없는 범위는 목록으로 시작합니다. 직접 고른 보기는 같은 페이지에서 부서나 업무를 바꿔도 유지합니다. 모바일에서 업무를 선택하면 결과 제목으로 이동합니다. 확인 순서 필터로 연결 내규가 0건이 되면 **전체 보기**로 필터를 해제할 수 있습니다. 상위법령 연결을 끈 업무 지도와 부서 전체 지도는 같은 배치입니다. 업무(또는 부서) 노드를 위에 두고 확인 순서 열을 아래에 매달아, 연결선이 다른 규정을 가로지르지 않습니다. 규정이 있는 열만 그리며, 두 열까지는 1280px 이상 화면에서 스크롤 없이 보입니다.
   제목 아래에는 `담당 팀 · 업무 기준 · 관련 규정 N종` 한 줄만 두고, 탐색 범위의 자세한 설명은 **범위 설명**을 펼쳐 봅니다. 탐색 기준 전환·규정 검색·확인 순서·보기 전환은 한 줄에 모았습니다.
   지도 위의 **업무 기준 / 규정 참조 기준** 표시로 현재 탐색 기준을 구분합니다. 규정 검색이나 **연결된 다른 규정 보기**로 규정 참조 기준이 되면, 확인 순서가 현재 업무 기준이라는 범위를 함께 표시하고 왼쪽 업무 목록에도 안내합니다. **업무 기준**을 누르면 업무 지도로 돌아갑니다.
7. 지도에서 **먼저 확인 / 함께 확인 / 해당할 때**의 열 제목을 따라 탐색합니다. 첫 핵심 노드의 윤곽만 강조하고 키보드 초점이나 상세 패널을 자동 이동하지 않습니다. 반복되는 대형 시작 카드·배지·배경 띠는 표시하지 않습니다. 열이 없는 목록에서는 우선순위 배지를 유지합니다.
8. 노드를 선택하면 그 순서로 배치한 이유를 확인할 수 있습니다. 규정 중심 탐색에서도 현재 업무의 우선순위를 유지하고, 그 업무에서 판단하지 않은 이웃 규정은 **순서 미평가**로 분리합니다. 인용 횟수로 순위를 부여하지 않습니다.
9. 선택 전 근거 패널은 업무 요약·검토 범위·미검토 상태를 보여줍니다. 선택 후에는 해당 규정의 연결 이유·적용 조건·근거 조문을 보여줍니다. 목록 모드에서는 지도용 범례·선 안내·확대 도구를 숨기고, 선택 규정의 참조 관계 수는 "지도에서 확인"으로 안내합니다. 좁은 화면에서 목록의 규정을 선택하면 근거 영역으로 이동하며, 상단에 고정되는 **규정 목록으로 돌아가기**로 선택했던 카드 위치에 돌아갑니다.
10. **규정 전문 보기**는 저장소 추출본 전체를 별도 읽기 화면으로 엽니다. 본문·부칙·별표/별지 구분, 목차 이동, 규정 내 검색과 추출본 내려받기를 지원합니다. 근거 조문을 펼친 뒤 **규정 전체에서 보기**를 누르면 해당 조문으로 이동합니다. 지도 선택 상태는 닫은 뒤 유지됩니다. 추출본의 `**굵게**`, `<u>`·`<sup>`, `\_` 같은 변환 기호는 서식으로 표시합니다. 각주 표시 `**`나 `010-****-****` 같은 원문 기호는 그대로 둡니다. 좁은 화면에서는 추출본 안내와 목차를 접어 본문 영역을 확보합니다. 전문 화면과 규정 상세에는 **ALIO 공식 게시 페이지**, **공식 원본 파일**, 판본(개정일), 저장소 수집일을 함께 표시해 추출본을 공식 원문과 바로 대조할 수 있습니다.

## 상위법령 지도

상위법령 매핑이 있는 업무·부서·규정 참조 지도는 처음부터 내규와 상위법령을 함께 그립니다. 왼쪽은 현재 범위의 내규, 오른쪽 보라색 노드는 외부 법령·행정규칙 등입니다. 여러 내규가 같은 법령과 연결되면 법령 노드 하나로 선이 모입니다. 어느 쪽 카드에 마우스를 올리거나 키보드 초점을 두어도 상대편 카드와 연결선이 함께 강조됩니다. 보라색 선을 클릭하거나 키보드로 선택하면 해당 내규와 법령 사이의 연결 근거가 열립니다. 법령 카드에서는 공식 원문과 연결된 내규를 탐색할 수 있습니다. **상위법령 연결**을 끄면 기존 내규 배치로 돌아갑니다. **상위법령 지도**에서 파란색 내규와 보라색 외부 문서 사이를 양방향으로 탐색할 수 있습니다. 두 종류 모두 이름으로 검색할 수 있고, 매핑표에 적힌 옛 제명이나 다른 표기로도 외부 문서를 찾을 수 있습니다.

`law_mapping.json`은 제공된 2026-11-06 엑셀의 **내규목록** C열을 옮긴 스냅샷입니다. 149개 내규 행 중 101개에 개별 외부 문서와의 연결 362건이 있습니다. 각 연결에는 셀 주소와 표 기재명을 보존합니다. 빈 셀은 기재 없음으로 처리하고, 같은 행의 중복 명칭은 한 번만 연결합니다. 관련 내규나 개별 제명이 없는 포괄 문구는 해당 행의 참고 내용에 남깁니다.

공식 제명과 식별자는 2026-11-10에 `korean-law-mcp`의 `search_law`, `search_admin_rule`, `search_treaties`로 대조했습니다. 폐지된 문서는 연혁으로 연결하고, 식별자를 대조하지 못한 명칭은 검색 링크를 제공합니다. 법률명 기재가 시행령도 포함한다는 표의 주석에 따라 확인한 시행령 원문을 법률 상세에 함께 표시합니다. 이 매핑은 문서 단위의 관련성만 담고 있습니다. 개별 조문의 위임 관계나 업무별 적용 판단은 별도 확인이 필요합니다.

각 연결의 **내규 인용 근거**는 매번 빌드할 때 현재 내규 본칙에서 인용부호 안의 법령명을 찾아 해당 조문과 문단을 표시합니다. 법령명 바로 뒤에 조·항·호·목이 명시되면 같은 인용 문단 아래에 대조한 외부 조문의 발췌, 판본과 원문 링크를 표시합니다. `law_excerpts.json`은 2026-11-10에 korean-law-mcp와 공식 공개본을 대조한 오프라인 스냅샷입니다. 키는 인용된 제명과 조문 위치이며 옛 제명은 해당 연혁 판본에 연결합니다. 법령명만 인용한 문단은 정의·절차·요건을 해당 법령 원문과 대조해 확인한 조문을 **상위법령 발췌 · 참고 조문**으로 표시합니다. 검토 결과는 내규명, 조문, 인용 문단의 SHA-256에 묶여 있어 내규 문구가 바뀌면 자동으로 해제됩니다. 약칭 정의 뒤에 조문 번호를 직접 명시한 경우에도 직접 인용으로 처리합니다. 포괄적 열거나 원문 미확인으로 조문을 특정할 수 없는 경우에는 그 사유를 표시합니다. 별도로 작성한 연결 설명은 근거 조문 본문의 해시가 일치할 때만 제공하며, 이해를 돕는 외부 참고 조문은 별도로 표기합니다.

엑셀 교체 시 `law_mapping.json`의 행·원표기·파일 해시를 갱신하고 공식 식별자를 다시 확인한 뒤 위의 빌드와 번들 명령을 실행합니다. 일반 빌드와 오프라인 탐색은 엑셀, MCP 접속 또는 API 키 없이 동작합니다.

### 외부 조문 주간 변경 PR

GitHub Actions의 **Weekly external law review**가 매주 월요일 09:23(한국시간)에 실행됩니다. Actions의 **Run workflow**로도 실행할 수 있습니다. `law.go.kr` 공개 페이지에서 법령의 고정 ID, 행정규칙의 고정 ID와 일련번호, 실제 시행일을 대조하며 API 키는 필요하지 않습니다. 현재 조회 대상은 고정 판본을 제외한 기존 발췌입니다. 법령명만 있는 관계에 새 참고 조문을 선정하는 작업은 내용 검토를 거칩니다.

발췌·시행일·원문 링크 또는 행정규칙 식별자가 바뀌면 `auto/external-law-review` 브랜치에 검토 PR을 하나 생성하거나 갱신합니다. 조회 결과가 같으면 새 PR을 만들지 않습니다. 조문 삭제·이동 또는 법령 제명 변경이 확인되면 기존 발췌를 보존하고 대조할 판본을 표시합니다. 오프라인 스냅샷의 연혁·특정 훈령·조약·고정 공개본은 유지합니다. 조회 오류는 실행 요약에 문서별로 남기며 해당 문서의 데이터는 유지합니다. 불완전한 재조회나 사람이 수정한 열린 PR은 덮어쓰지 않습니다.

원문 조회의 타임아웃은 20초이며, 시간 초과, 연결 끊김, 일시적인 DNS·HTTP 오류는 요청당 최대 3회 시도합니다. 실패한 요청과 재시도 성공 로그에는 법령명·조회 단계·시도 번호와 각 시도의 경과 시간(재시도 대기 제외)을 남깁니다. 일시적인 조회 실패만 남으면 첫 시도의 변경안을 보류하고 새 GitHub 러너에서 60초 뒤 전체 대조를 한 번 더 수행합니다. 문서별 오류 종류와 메시지는 Actions 로그와 실행 요약에서 확인할 수 있습니다. 식별자 불일치·시행일 역행 등 검증 오류나 두 번째 대조까지 남은 오류는 실패로 보고합니다.

검토자는 파일 차이에서 원문·판본과 해당 내규 문맥을 확인한 후 PR을 병합합니다. 병합된 데이터는 기존 Pages 워크플로로 배포됩니다. 로컬에서 실행하려면 Python 3.12와 lxml을 준비하고 저장소 루트에서 `python tools/law-sync/sync.py --report /tmp/law-review.md`를 실행합니다. 이 명령은 작업 사본에 변경안을 기록합니다.

## 데이터와 한계

- `build.py`는 `data/extracted/`의 개별 규정 Markdown을 읽습니다. 기존 검색 인덱스·의미 벡터를 수정하거나 새로 계산하지 않습니다.
- `data.js`는 재생성 가능한 로컬 빌드 산출물입니다. 원문 개정 후 다시 빌드해야 합니다. 원문 SHA-256이 메타데이터에 포함됩니다.
- 부서 범위는 별표 4(본사·국내사무소)와 별표 5의 해외사무소 칸입니다. 48개 해외사무소는 업무분장이 같아 **해외사무소** 하나로 묶고, 별표 5의 구분(기획, 사업집행(프로젝트) 등 9개)을 하위 묶음으로 둡니다. 사무소 이름(예: 베트남사무소)으로 찾아도 해외사무소가 나옵니다(사무소 목록은 별표 2의 2). 같은 행의 본사 칸과 두 칸에 걸친 ※ 주석은 업무분장 원문 확인에 참고로만 보여 주며, 본사 업무는 별표 4 부서에서 다룹니다. 사무소별 관할지역·정원(별표 7)은 반영하지 않았습니다.
- 규정 간 연결은 **본칙에 명시된 전체 규정명 참조**입니다. 공백·줄바꿈을 정규화하며, 명시된 대상 조문은 본칙 내 존재 여부를 확인합니다. 「이름」(이하 "약칭"이라 한다) 제N조처럼 약칭 정의가 끼어도 대상 조문을 잇고, "국내·국외 여비규정"처럼 앞말을 나란히 쓴 표기는 두 규정을 모두 연결합니다(이때 조문 번호는 어느 쪽인지 모호해 두지 않습니다). 같은 규정 안에서 약칭을 정의했다면 이후 "규정 제9조"처럼 약칭으로 쓴 조문도 그 규정의 조문으로 잇습니다. "이 규정"처럼 자기 자신을 가리키는 말과, 두 규정에 같은 약칭을 붙인 경우는 제외합니다. 다른 규정에서 정의한 약칭·간접인용·별표 내부 참조는 추출하지 않아 관계가 누락될 수 있습니다.
- **업무 연결에 키워드·유사도 추천을 사용하지 않습니다.** `content_reviews.json`은 AI가 실제 업무분장과 근거 조문 전문을 읽고 작성한 역할·이유·적용조건·인용문·검토범위입니다. 기관의 공식 적용 판정은 아닙니다.
- 검토한 업무마다 **먼저 확인 / 함께 확인 / 해당할 때**의 탐색 우선순위와 판단 이유를 별도로 작성합니다. 동일 규정도 업무에 따라 순서가 달라집니다. 예를 들어 시설지원 지침은 일반 사업관리에서는 조건부 분기이고, 건축·CM 수행지원 업무에서는 먼저 확인할 규정입니다. 이 순서는 법적 효력·준수 의무의 우열이나 확률 점수가 아닙니다.
- 별표 4의 47개 부서 413개 업무를 검토해 **410개 업무에 부분 검토 연결**을 작성했습니다. 3개 업무(재정사업 성과보고·자율평가, 재정경제부 업무연락방, 동반성장 평가 대응)는 내부 규정에서 직접 근거를 찾지 못해 "직접 관계 미확정"으로 두고 확인한 규정과 공백을 기록합니다. 이전에 추가 자료가 필요하다고 표시했던 7개 업무는 제공된 규정 범위에서 특정 행위의 직접 근거·관련 원칙·공통 처리절차를 구분하여 연결했습니다. 업무 전체의 전용 근거를 확정한 것으로 표시하지 않으며, 추가 자료 제출을 지도 이용의 조건으로 두지 않습니다. 이는 업무 내 모든 세부 실행기준을 검토했다는 의미가 아닙니다.
- 해외사무소(별표 5) 68개 업무를 2026-11-06에 같은 방식으로 검토했습니다. 65개 업무에 179개 연결을 작성했고, 이 중 18개 업무는 업무 전체를 정한 조문이 없어 관련 원칙·공통 절차만 연결한 "직접 근거 미확정"입니다(CPS·CP 작성 지원, 공여국 회의, 긴급구호 등). 3개 업무(봉사단 국별전략 수립, 통합 플랫폼 기능 이행·평가 지원)는 직접 관계 미확정으로 둡니다. 근거는 국별협력사업 규정 제8조·제14조·제17조, 사후관리지침 제2조, 봉사단 시행세칙 제16조처럼 **사무소의 역할을 직접 정한 조문**을 우선했습니다. 다만 '먼저 확인' 47건 중 24건은 조문 주체가 '협력단'으로만 적혀 있어, 그 행위를 규율하는 규정이라는 뜻이지 본사와 사무소의 분담까지 정한다는 뜻은 아닙니다. 분담은 아래의 위임전결 별표에서 일부 확인할 수 있습니다. 별표 5의 '관리요원'을 해외봉사단 코디네이터로 보는 연결은 두 명칭을 같다고 정한 조문이 없어 '함께 확인'에 둡니다. 새로 인용한 141개 조문은 MCP `verify_citation`으로 실재를 확인했고, 무작위 15건을 조문과 다시 대조했습니다.
- **위임전결 참고(2024.02.13 기준, 현행 아님)**: 위임전결규정 별표 1-2(단위업무별 위임전결 세부사항)에는 '사무소장' 전결 열과 기안 주체(본사·사무소·본/사) 열이 있어 본사와 사무소의 분담을 단계별로 보여 줍니다. 현행본(2025.12.31 개정)은 이 별표를 '별도 파일 참조'로만 싣고 ALIO에 그 파일이 없어, ALIO에 마지막으로 공개된 2024.02.13 개정본 zip(fileNo 194590)의 엑셀 표를 씁니다. `delegation_annex.py`가 이 zip의 해시를 확인한 뒤 표준 라이브러리로 1,152개 행을 `delegation_annex_2024.json`에 뽑고, 빌드는 행마다 해시를 다시 확인합니다. 해외사무소 68개 업무를 네 가지로 나눴습니다. **사무소 몫 항목 있음** 31개(사무소장 전결이나 사무소 기안 항목이 있음, 예: 현지입찰은 추정가격 50억 원 미만이면 사무소장 전결), **본사 몫 항목만 있음** 19개(같은 절차의 본사 항목만 있음, 국내초청연수·긴급구호·사업평가 등), **가까운 항목만 있음** 6개(같은 업무인지 확정하지 못한 항목, 예: 동료검토 ↔ PD 심사·TAG), **대응 항목 없음** 12개(CPS 작성 지원, 현지 법규 분석, 민관협력 타당성 조사, 재건수요 발굴, 수혜자 평가, 통합플랫폼 등)입니다. 처음에는 21개를 '찾지 못함'으로 두었으나, 표 전체 키워드 검색과 사용하지 않은 사무소 표시 행 133개 대조로 다시 확인해 9개를 고쳤습니다. 분류는 빌드에서 행과 맞는지(사무소 몫이면 사무소 표시 행이 있어야 함) 검사합니다. 표 첫머리의 공통사항(출장·회의 개최·예산 집행 등)은 업무별 기준이 없을 때 적용된다고 적혀 있어, 대응 항목이 없는 업무에도 적용될 수 있습니다. - 규정명 참조 자동 추출은 기존대로 전체 코퍼스를 대상으로 하며, 그중 8개 관계에 내용검토 설명을 추가했습니다. 자동 추출을 의미 검토 완료나 법적 위계 확정으로 표시하지 않습니다.
- 근거 인용은 "…에 한하여"처럼 범위를 한정하는 문장의 열거 부분을 잘라내지 않습니다. 잘라내면 적용 범위가 실제보다 좁아 보이기 때문이며, 테스트가 전체 인용을 검사합니다.
- 2026-11-05에 무작위 표본(규정 간 참조 20개·업무 연결 20개)을 평가하고, 확인된 오류 유형(업무와 안 맞는 공용 이유, 다른 제도 연결, 범위를 좁히는 잘린 인용, 업무 원문에 명시됐는데 낮게 잡힌 확인 순서, 링크 조건이 스스로 제외한 대상에 붙은 연결)으로 전체 연결을 선별해 원문과 다시 대조했습니다. 그 결과 업무 33개의 연결 35건을 고쳤습니다. 2026-11-06에는 개별로 읽지 않은 나머지 후보 166쌍에서 무작위 20개를 다시 평가했습니다. 결과는 적절 18·부분 2·부적절 0입니다(문제 비율 10%, 95% 신뢰구간 약 1~32%). 두 건 모두 공용·템플릿 이유가 업무와 맞지 않는 유형이라 해당 연결을 고쳤습니다.
- 이어서 "해당 업무 중 …를 수행하는 경우 함께 확인합니다" 같은 공용 문장으로 남아 있던 확인 순서 이유 579개를 업무별로 다시 썼습니다. 이유마다 업무분장의 어느 부분이 어느 조문과 닿는지 적고, 적은 조문 번호가 실제로 있는지 테스트가 검사합니다. 다시 쓰면서 확인 순서 33건을 조정했습니다. 30건은 업무 원문에 없는 행위(MOU 체결, 조사연구 과제 등)에 "함께 확인"으로 붙어 있던 연결을 "해당할 때"로 내린 것으로, 해당 규정의 적용범위나 연결 자신의 조건이 그 행위를 할 때로 한정되어 있습니다. "먼저 확인"이 바뀌는 3건은 조문 원문과 다시 대조했습니다.
- `reviews.py`는 작성된 연결을 불러오고 검증하기만 합니다. 업무분장·근거 규정 파일·조문 본문 해시가 검토 당시와 달라지면 해당 연결을 숨기고 재검토 필요로 표시합니다. 재빌드는 검토 기록의 해시를 자동 갱신하지 않습니다.
- 검토 조문 범위와 미검토 영역은 화면 및 JSON에 기록합니다. 규정의 목적·적용범위와 해당 조문 전문을 검토했으며, 관련 별표·서식·외부 법령까지 모두 검토한 것은 아닙니다.
- 시행일 예외는 데이터 안내에서 원문을 제공합니다. 날짜별 조직 상태를 자동 복원하지 않으므로 현재 담당 확정에는 부칙을 함께 확인해야 합니다.
- 공개 규정의 저장소 스냅샷을 사용하며, 실행 시 공식 원문 최신성을 확인하지 않습니다. 대신 `data/sources.json`의 ALIO 게시 페이지(`page_url`)·파일 번호와 저장소 수집일(`collected_at`)로 공식 원문 링크를 만듭니다. `collected_at`은 해당 판본의 추출본을 저장소에 반영한 날이며, ALIO 동기화가 내용이 바뀐 규정에만 새 날짜를 기록합니다. 기존 값은 각 추출본의 마지막 반영 커밋 날짜(KST)로 채웠습니다. 값이 없으면 링크를 추측하지 않고 "기록 없음"으로 표시합니다.
- 전문 화면은 원본 파일에서 변환된 Markdown 텍스트 전체를 사용합니다. 관계 분석에서 제외하는 부칙·삭제 조문·별표도 삭제하지 않습니다. 문서 구간을 다시 합치면 저장소 파일과 정확히 일치하도록 검사합니다. HTML/Markdown 표는 안전하게 표시하지만, 이미지 표·도식 및 추출 과정에서 빠진 부분은 원본 HWP/PDF를 확인해야 합니다. 화면의 안내와 개정일로 이 범위를 표시합니다.
- 기존 공개 MCP 서버와 배포 설정은 변경하지 않습니다. OpenCrab 연동이나 그래프 팩 내보내기는 아직 구현하지 않았습니다.

## 내용검토 추가

업무분장과 규정의 목적·적용범위, 근거 조문 전문·예외를 읽은 뒤 `content_reviews.json`에 명시적으로 작성합니다. `links`의 역할·이유·적용조건과 근거 인용, `duty_reviews`의 정확한 부서·업무 및 검토범위·누락사항을 함께 기록합니다. `source_snapshots`의 파일 해시와 조문 해시는 그 내용을 다시 검토했을 때만 갱신합니다. 모든 규정을 읽었다거나 업무 전체를 검토했다고 범위를 확대하여 표시하지 않습니다.
